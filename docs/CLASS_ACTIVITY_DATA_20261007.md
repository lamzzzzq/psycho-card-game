## 1. 200 人同时玩：怎么保证顺利

### 1.1 服务器容量（已验证）

| 测试 | 结果 |
|---|---|
| 9/16 压测 500 人登录（Micro 规格） | 500/500 全部登录，单次约 0.3 秒 |
| 9/15 压测 500 人对局（125 桌） | 全部打完、全部存档，零错误 |
| **10/7 课前演练 200 人（真登录＋真对局）** | **200/200 登录，61 秒内全部完成，每人一次就成功；50/50 桌打完并存档；出现 2 次实时连接短暂断开，都自动恢复了，不影响结果** |

- 演练用的是五大模型。HEXACO、SD4 跟它共用同一个数据库和同一套实时连接，负载情况完全一样。
- SD4 联机线上从来没存过一局，所以我另外用 SD4 自己的存档代码写了一局测试数据进线上库，确认三张表都写进去了、导出也读得到，验完已删除。
- 当前配置：Supabase Pro + Micro 规格，登录限流 3000 次/5 分钟。**上课前不需要升级，也不用分批登录。**

### 1.2 课堂当天真正的风险和对策

| 风险 | 对策 |
|---|---|
| **当场注册**：注册要收邮件验证码，经 Resend 发送。200 人同时注册可能撞到发信额度（免费档好像每天只有 100 封，要查我们是哪个档），学校邮箱收信也可能很慢 | **课前一周让学生先注册、做完测评**，当天只需要登录 |
| 忘记密码 | 找回密码也要发邮件，同样受额度影响。课前提醒学生记好密码 |
| 校园 Wi-Fi | 200 台设备挤同一个 AP，比我们的服务器更容易先出问题。可以让学生备好手机流量 |
| **玩了单机** | **单机局的对局成绩不存数据库。** 课堂活动必须用联机（单机只会记下小测成绩） |
| 存档失败 | 已有保护：对局结束先存到房主设备上，传成功才删；没传上的，房主下次打开大厅或对局页时自动补传（24 小时内）。小测成绩也是同样的机制 |

### 1.3 当天流程建议

1. 课前一周：学生注册并完成要用到的模型测评（五大 / HEXACO / SD4）。
2. 当天：登录 → 进对应模型的联机大厅 → 4 人一房打一局。
3. 对局结束后：让学生在结算页点「立即測試」做完 4 题小测，**一定要点到「看結果」才会记录**。
4. 课后：运行导出（§3），用 `--since 当天日期` 只取当天的数据。

## 2. 记录了什么数据

> 全部以**学号**为单位。所有分数都只有老师后台能读，学生之间互相看不到，也读不回自己写进去的数据。

### 2.1 测评（三套模型）

- **每做一次存一行**：每题选了什么（五大 50 题、HEXACO 60 题、SD4 28 题）、算出的分数、提交时间。
- 重做也会再存一行，旧的不覆盖。导出时同时给出「最新一次」分数和测评次数。
- 来源 `manual` 表示手动填分，这种没有逐题答案。

### 2.2 对局（只有联机局）

一人一局一行：

| 字段 | 意思 |
|---|---|
| 申报组数 | 这局碰/归档成功了几组（得分依据，满 5 组就胡） |
| 碰成功 / 碰失败 | 碰牌判定的成功、失败次数 |
| 食胡成功 / 食胡失败 | 宣告胡牌的成功、失败次数 |
| 名次、胜出 | 1 = 第一名 |
| 剩余手牌、设定轮数 / 实际轮数、人数、房号、开始 / 结束时间 | — |
| 中断局 | 房主中途退出（这种局没有胜负） |

> 「完成局」= 有胜负结果的局，也包括其他人都退出、剩下一人躺赢的情况。

### 2.3 局末小测（本次新增）

- 每次答完 4 题存一行：3 题知识卡题 + 第 4 题人格维度题。
- 记录每题的题目、学生选了什么、正确答案、对不对，以及模型、单机还是联机、房号、第几次作答。
- 「再測一次」答完会再存一行；**中途点「離開」不记录**。
- 正确率按每题的对错重新计算，不采用前端传上来的分数字段（防学生手动造假）。

### 2.4 刻意没有记录的（你确认过不需要）

- 每一步出牌、弃牌、碰的时候选了哪个维度（动作日志）。
- 单机局的对局成绩。

## 3. 怎么导出数据

### 方法 A：一键导出 Excel（推荐）

在项目目录 `~/PsychoCardGame` 运行：

```bash
npx tsx scripts/export-class-data.ts                     # 全部数据
npx tsx scripts/export-class-data.ts --since 2026-10-15  # 只要某天（香港时间零点）之后的
npx tsx scripts/export-class-data.ts --out ~/Desktop/某班.xlsx
```

桌面会生成 `人格麻將_課堂數據_YYYYMMDD.xlsx`，共 7 张表：

| 工作表 | 内容 |
|---|---|
| 說明 | 口径说明 |
| **學生匯總** | **一个学号一行**：三模型最新分数＋测评时间＋次数、完成局/中断局、各模型局数、胜场、申报组数合计/每局平均、平均名次、碰成功/失败、食胡成功/失败、小测次数＋正确率、最后活动时间 |
| 測評_五大 / 測評_HEXACO / 測評_SD4 | 每次测评一行，Q1…Qn 逐题答案 |
| 對局明細 | 一人一局一行 |
| 小測明細 | 每次小测一行，每题的 ✓/✗ 和作答内容 |

- 时间都是香港时间，存成真正的日期格式，可以直接排序、筛选。
- 加了 `--since` 的话，汇总表只列这段时间有活动的学号，但汇总表里的数字是全期累计。要看当天的数字，用明细表筛选。

> ⚠️ **导出要用 Supabase 管理 token**（脚本会自动从本机钥匙串读取）。如果按计划撤销了这个 token，方法 A 就用不了，要么另建一个只读 token，要么改用方法 B。

### 方法 B：Supabase 后台直接导（不用跑命令）

Dashboard → **SQL Editor** 运行以下任一句 → 结果右上角 **Export → CSV**：

```sql
select * from class_data.students;     -- 学生汇总（一学号一行）
select * from class_data.assessments;  -- 测评明细（answers 是 JSON）
select * from class_data.games;        -- 对局明细
select * from class_data.quizzes;      -- 小测明细（items 是 JSON）
```

### 汇总表的列名对照（方法 B 的 CSV 是英文列名）

| 列名 | 意思 |
|---|---|
| `bf_o / bf_c / bf_e / bf_a / bf_n` | 五大最新分数（N = 神经质，高分 = 易焦虑） |
| `hx_h / hx_e / hx_x / hx_a / hx_c / hx_o` | HEXACO 最新分数 |
| `sd4_m / sd4_n / sd4_p / sd4_s` | SD4 最新分数（M 馬基維利主義 / N 自戀 / P 病態人格 / S 虐待） |
| `*_latest_at`、`*_attempts` | 最新测评时间、测评次数 |
| `games_completed / games_interrupted` | 完成局 / 中断局 |
| `games_big_five / games_hexaco / games_sd4` | 各模型局数 |
| `wins`、`declared_total`、`declared_avg`、`rank_avg` | 胜场、申报组数合计、每局平均申报、平均名次 |
| `pong_success / pong_fail / hu_success / hu_fail` | 碰、食胡的成败次数 |
| `quiz_attempts`、`quiz_correct_rate` | 小测次数、正确率（0–1） |
| `last_active_at` | 最后活动时间（UTC，比香港时间晚 8 小时） |

## 4. 还能统计什么（数据已经有，按需再算）

- **识人准确率**：碰成功 ÷ (碰成功 + 碰失败)、食胡成功 ÷ (食胡成功 + 食胡失败)。
- **人格 × 表现**：比如外向分高的人，平均申报组数或胜率是不是更高（汇总表直接做相关分析）。
- **测评前后变化**：同一学号多次测评的分数差（测评明细表的「第幾次」列）。
- **作答质量**：逐题答案里有没有整排填同一个数字（直线作答）。
- **学习效果**：小测正确率随作答次数的变化、维度题（第 4 题）和知识卡题的正确率对比。
- **课堂参与度**：每人局数、中断局比例、最后活动时间。
